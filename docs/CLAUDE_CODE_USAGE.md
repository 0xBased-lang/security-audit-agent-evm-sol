# Claude Code Integration Guide

Complete guide for using the Security Audit Framework with Claude Code.

## Overview

This framework is designed to work seamlessly with Claude Code, leveraging AI orchestration to run comprehensive security audits on blockchain smart contracts.

## Getting Started

### 1. Project Setup

Copy the `.claude` directory to your project:

```bash
# From your smart contract project directory
cp -r /path/to/security-audit-agent-evm-sol/.claude ./.claude
```

### 2. Verify Installation

In Claude Code, run:

```
/audit --help
```

Or use the CLI directly:

```bash
node /path/to/security-audit-agent-evm-sol/src/cli.js tools
```

## Slash Commands

### `/audit` - Primary Audit Command

```bash
# Basic usage
/audit ./contracts

# With mode specification (use --mode flag)
/audit ./contracts --mode quick      # Fast scan (2-5 min)
/audit ./contracts --mode standard   # Balanced (5-15 min)
/audit ./contracts --mode deep       # Comprehensive (15-30 min)

# With format
/audit ./contracts --format markdown
/audit ./contracts --format html
/audit ./contracts --format json

# Or use CLI directly
node src/cli.js audit --project ./contracts --mode quick
```

### Audit Workflow

When you run `/audit`, Claude Code will:

1. **Pre-Audit Validation** (30s)
   - Run `.claude/hooks/pre-audit.sh`
   - Check tool availability
   - Estimate complexity
   - Validate project structure

2. **Agent Deployment** (varies by mode)
   - Spawn `security-orchestrator` agent
   - Orchestrator spawns specialized sub-agents in parallel
   - Agents run appropriate tools

3. **Analysis** (varies by mode)
   - Static analysis (Slither, Mythril, Foundry)
   - Adversarial testing (if standard/deep mode)
   - Invariant checking (if standard/deep mode)

4. **Synthesis** (1-2 min)
   - Cross-reference findings
   - Filter false positives
   - Calculate security score
   - Generate report

5. **Post-Audit** (30s)
   - Run `.claude/hooks/post-audit.sh`
   - Create summary report
   - Send notifications (if configured)

## Agent System

### Understanding Agents

The framework uses a hierarchical agent system:

```
You (Claude Code user)
    │
    └── security-orchestrator (main agent)
            │
            ├── static-analysis-agent
            │       ├── slither-agent
            │       ├── mythril-agent
            │       └── foundry-agent
            │
            └── adversarial-agent
                    ├── mev-hunter-agent
                    ├── flash-loan-detector
                    └── governance-attack-agent
```

### Agent Model Selection

- **Lead agents** (orchestrator, analysis): Use Sonnet for complex reasoning
- **Tool agents** (slither, mythril): Use Haiku for fast, focused tasks

### Parallel Execution

Agents run in parallel when possible. Claude Code automatically:

1. Spawns all independent agents in a single message
2. Waits for all agents to complete
3. Aggregates results

## Output Files

After an audit, you'll find:

```
audit-results/
├── comprehensive-report.md   # Main report (human-readable)
├── comprehensive-report.json # Machine-readable report
├── adversarial-findings.json # Adversarial testing results
├── AUDIT_SUMMARY.md          # Executive summary (generated by post-audit hook)
└── audit_metrics.csv         # Historical metrics (appended each run)
```

**Note**: File generation depends on audit mode and hooks configuration. The post-audit hook (`post-audit.sh`) generates the summary and calculates the security score.

## Security Score

The framework calculates a security score (0-100):

```
Score = 100 - (CRITICAL × 25 + HIGH × 10 + MEDIUM × 5 + LOW × 1)
```

| Score | Grade | Meaning |
|-------|-------|---------|
| 90-100 | A | Excellent - minimal issues |
| 80-89 | B | Good - minor issues only |
| 70-79 | C | Fair - some concerns |
| 60-69 | D | Poor - significant issues |
| 0-59 | F | Critical - major vulnerabilities |

  --project ./contracts \
  --mode deep \

Target specific vulnerability types:

```bash

  --project ./contracts \
  --strategies mev,flash_loan,oracle_manipulation
```

### Invariant Testing

Run comprehensive invariant tests:

```bash
node src/cli.js invariants \
  --project ./contracts \
  --runs 10000 \
  --depth 50
```

## Interpreting Results

### Severity Levels

- **CRITICAL**: Immediate fund loss risk - fix before deployment
- **HIGH**: Significant vulnerability - must fix
- **MEDIUM**: Security concern - should fix
- **LOW**: Best practice violation - consider fixing
- **INFORMATIONAL**: Improvement suggestion

### False Positives

The framework automatically filters common false positives:

- Test contract issues
- Mock implementations
- Development helpers
- Intentionally vulnerable examples

To mark a finding as false positive, add a comment:

```solidity
// @audit-ok: Intentionally unchecked for gas optimization
```

## Troubleshooting

### Tools Not Found

```bash
# Check tool availability
node src/cli.js tools

# Install missing tools
pip install slither-analyzer mythril
curl -L https://foundry.paradigm.xyz | bash && foundryup
```

### Audit Taking Too Long

- Use `--quick` mode for initial scan
- Focus on specific contracts: `--project ./contracts/Token.sol`
- Skip formal verification for faster results

### No Vulnerabilities Found

If audit finds nothing:
1. Verify contracts are in correct path
2. Check contract file extensions (`.sol` for Solidity)
3. Run `slither` directly to verify it works
4. Check for compilation errors

### Memory Issues

For large projects:
```bash
# Increase Node.js memory
export NODE_OPTIONS="--max-old-space-size=8192"
```

## Best Practices

### Pre-Deployment Checklist

1. ✅ Run `/audit ./contracts --mode deep` on all contracts
2. ✅ Fix all CRITICAL and HIGH issues
3. ✅ Review all MEDIUM issues
4. ✅ Run invariant tests with 10000+ iterations
5. ✅ Test on forked mainnet
6. ✅ Get security score ≥80 (Grade B)

### CI/CD Integration

Add to your GitHub workflow:

```yaml
name: Security Audit
on: [push, pull_request]

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Install tools
        run: pip install slither-analyzer

      - name: Run quick audit
        run: node src/cli.js audit --project . --mode quick

      - name: Run post-audit hook for score
        run: ./.claude/hooks/post-audit.sh ./audit-results ${{ github.repository }}

      - name: Check for critical issues
        run: |
          # Check adversarial findings for critical issues
          if [ -f audit-results/adversarial-findings.json ]; then
            critical=$(jq '[.findings[] | select(.severity == "CRITICAL")] | length' audit-results/adversarial-findings.json)
            if [ "$critical" -gt 0 ]; then
              echo "Found $critical critical issues!"
              exit 1
            fi
          fi
```

### Regular Auditing

- Run quick audits on every PR
- Run standard audits weekly
- Run deep audits before major releases
- Re-audit after any dependency updates
